# Threat model initial

Date : 2026-10-06. Auteur : l'agent, sur délégation (PD-0003). Statut : version initiale, à réviser avant toute mise en production et à chaque nouvelle surface exposée.

Ce document décrit ce qui est **construit et testé** aujourd'hui (prototypes en mémoire, sans authentification, sans réseau public) et ce qui est **prévu mais pas encore là**. Il ne prétend pas qu'un contrôle existe quand il n'est qu'une intention : chaque ligne dit lequel des deux.

## 1. Périmètre et méthode

- Périmètre : plateforme de production de podcast vidéo décrite dans le prompt maître (studio temps réel LiveKit, enregistrement serveur par piste, présentations HTML collaboratives, régie, serveur MCP, post-production).
- Méthode : acteurs, actifs, frontières de confiance, puis menaces par catégorie STRIDE (usurpation, altération, répudiation, divulgation, déni de service, élévation de privilège), reliées à la liste du §27.3 du prompt maître.
- Hors périmètre de cette version : sécurité du poste de chaque participant, de l'hébergeur, de la chaîne d'approvisionnement logicielle au-delà des dépendances directes, aspects légaux de l'enregistrement et du traitement des voix (décisions du propriétaire, voir `docs/open-questions.md`).

## 2. Acteurs

| Acteur                         | Confiance         | Remarque                                                                                                                                                            |
| ------------------------------ | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Producer (propriétaire, régie) | élevée            | Peut démarrer l'enregistrement, composer le Program, publier. Son navigateur compose le Program ([ADR-0003](adr/ADR-0003-composition-du-program-cote-producer.md)). |
| Host, Co-host                  | moyenne           | Agissent dans leur périmètre d'épisode.                                                                                                                             |
| Guest (invité)                 | faible            | Lien d'invitation, appareil inconnu, aucun contrôle sur son poste.                                                                                                  |
| Éditeur, Viewer                | moyenne, faible   | Accès différé aux enregistrements ; lecture seule.                                                                                                                  |
| Agent IA via MCP               | **non fiable**    | Peut se tromper, être manipulé par le contenu qu'il lit, rejouer des appels. Lié à un credential, un podcast, des scopes.                                           |
| Présentation HTML              | **non fiable**    | Code arbitraire écrit par un humain ou une IA, exécuté dans le navigateur de tous les participants.                                                                 |
| Attaquant externe sans compte  | hostile           | Cible les points d'entrée publics : invitations, WebSocket, signalisation, téléversements, URLs signées.                                                            |
| Participant malveillant        | hostile           | Invité ou compte légitime qui sort de son rôle.                                                                                                                     |
| Opérateur de la plateforme     | élevée, à auditer | Accès aux serveurs et aux sauvegardes.                                                                                                                              |

## 3. Actifs

1. **Enregistrements bruts** (pistes audio et vidéo par participant) : le contenu le plus sensible et le plus coûteux à perdre. Perte, fuite ou altération.
2. **Identités et droits** : comptes, rôles, credentials MCP, jetons de salle LiveKit.
3. **Contenus d'épisode** : conducteurs, notes, présentations, transcriptions (texte de ce qui a été dit).
4. **Assets de marque** et configuration des thèmes.
5. **Disponibilité du live** : un direct interrompu ne se rejoue pas.
6. **Secrets** : clés API LiveKit, clés du stockage, clés des fournisseurs IA.
7. **Budget** : calcul média, stockage, appels de modèles IA.

## 4. Frontières de confiance et flux

```text
 Navigateur Producer ──┐                      ┌── LiveKit (SFU) ── Egress (disque local persistant)
 Navigateur Guest   ───┼── WebRTC / signalisation ──┘                        │
 Navigateur Host    ───┘            │                                       ▼
        │                           │                           Envoyeur vérifié (SHA-256) ─► Stockage objet
        │ HTTPS / WebSocket         │
        ▼                           ▼
   API plateforme ── commandes (régie) ── serveur collaboratif (Yjs) ── base de données
        ▲                    ▲
        │                    └── Présentations : iframe sandbox, origine dédiée, CSP
        └── Serveur MCP ◄── agents IA (credential, scopes, podcast)
```

Frontières, de la moins à la plus sûre : (1) Internet / navigateur d'un invité ; (2) iframe de présentation / application ; (3) application / API ; (4) API / services média ; (5) services / stockage et secrets. Tout ce qui franchit une frontière est revalidé de l'autre côté : le client n'est jamais une frontière de sécurité.

## 5. Menaces, contrôles et état

Légende de l'état : **testé** = contrôle présent dans le code et vérifié par des tests (mutations comprises) ; **conçu** = décision documentée, pas de code ; **absent** = rien encore.

### 5.1 Contrôle d'accès et identité

| Menace (§27.3)                                   | Contrôle                                                                                                                                                                                                             | État                                                                                                                                                                                                                             | Preuve                                                                      |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| IDOR, accès cross-tenant                         | Le podcast vient du credential, jamais de la requête ; toute lecture passe par (podcast, id) ; un id d'un autre podcast répond « introuvable ».                                                                      | **testé** pour MCP et l'Episode Factory ; **absent** pour l'API web                                                                                                                                                              | [POC 9](pocs/poc-09-mcp-episode-factory.md), AC-MCP-004, AC-FACTORY         |
| Élévation de privilège (UI, API, WebSocket, MCP) | Droits revérifiés par le serveur à chaque message (collab) et à chaque commande (régie) ; scopes MCP relus à chaque appel ; l'approbation humaine n'existe pas comme tool MCP ; approbateur = PRODUCER de l'épisode. | **testé** (collab, régie, MCP) ; rôles et authentification **absents**                                                                                                                                                           | [POC 6](pocs/poc-06-regie.md), [POC 7](pocs/poc-07-collaboration.md), POC 9 |
| Usurpation d'identité (jetons)                   | Authentification réelle, jetons de salle LiveKit courts, une identité par participant attribuée **par le serveur**.                                                                                                  | partiel : authentification interne (scrypt, sessions opaques, verrouillage, mêmes réponses pour compte inconnu) et jetons de salle de 2 h signés par le serveur **testés** (`apps/api`) ; MFA et fournisseur externe **absents** | [ADR-0013](adr/ADR-0013-noyau-serveur-api.md), `apps/api/test`              |
| Détournement de WebSocket (CSWSH)                | Vérification de l'en-tête `Origin` à la montée en WebSocket, ticket court à usage unique plutôt qu'un jeton dans l'URL (les URLs finissent dans les journaux et les proxys).                                         | partiel : contrôle d'`Origin` et taille de message **testés** dans `packages/collab` ; le jeton passe encore dans l'URL (ticket à usage unique **absent**)                                                                       | `packages/collab/test/collab.test.ts`                                       |
| CSRF                                             | Cookies `SameSite`, jetons anti-CSRF sur les mutations par cookie ; les API par jeton porteur n'y sont pas sujettes.                                                                                                 | **testé** : cookie `HttpOnly` `SameSite=Strict`, `Origin` exigé pour toute requête qui modifie l'état par cookie ; le jeton porteur n'est pas concerné                                                                           | `apps/api/test/api.test.ts`                                                 |
| Fuite de jeton                                   | Pas de jeton dans les URLs ni les journaux, rotation, expiration courte, révocation immédiate (déjà le cas des credentials MCP).                                                                                     | partiel : révocation MCP **testée**, le reste **absent**                                                                                                                                                                         | POC 9                                                                       |

### 5.2 Code non fiable : présentations HTML

| Menace                                                                   | Contrôle                                                                                                                                                                                                                | État                                                                                                                                                               | Preuve                                                                                             |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| XSS, évasion du bac à sable                                              | Origine dédiée, iframe `sandbox="allow-scripts"` sans `allow-same-origin`, CSP stricte avec `frame-ancestors` obligatoire, aucun accès aux cookies, au stockage, à `window.parent`.                                     | **testé** dans Chrome 154 : 24 attaques bloquées, 2 messages forgés rejetés, témoin négatif                                                                        | [ADR-0007](adr/ADR-0007-isolation-des-presentations-html.md), [POC 8](pocs/poc-08-html-sandbox.md) |
| XSS dans l'application elle-même (titres, noms, notes venant du serveur) | Gabarits qui échappent toute valeur interpolée, aucun script ni style en ligne, aucun gestionnaire d'événement, CSP `script-src 'self'`, pages servies par l'API (même origine), aucun jeton lisible par le JavaScript. | **testé** sans navigateur (aucune sortie ne contient de balisage issu des données, d'attribut `on…`, de `<script`, de `javascript:`) ; **non vérifié dans Chrome** | [ADR-0014](adr/ADR-0014-application-web-sans-framework.md), `apps/web/test`                        |
| Exfiltration par le réseau, SSRF depuis la page                          | CSP : aucune connexion sortante, aucune ressource externe. Validation statique (aide à l'auteur, pas une protection).                                                                                                   | **testé**                                                                                                                                                          | POC 8                                                                                              |
| Message `postMessage` hostile                                            | Liste fermée de messages validés par un schéma, vérification de la source et de l'origine.                                                                                                                              | **testé**                                                                                                                                                          | `packages/presentation-sandbox`                                                                    |
| Déni de service par une page gourmande                                   | Aucune limite de CPU ou de mémoire de l'iframe ; l'iframe peut figer l'onglet qui l'affiche. Mesure de la charge, minuteur de surveillance, chargement différé.                                                         | **absent**                                                                                                                                                         | limite documentée du POC 8                                                                         |
| Faille du navigateur lui-même                                            | Mise à jour de Chrome, isolation des sites. Non maîtrisable côté plateforme.                                                                                                                                            | résiduel                                                                                                                                                           | —                                                                                                  |

### 5.3 Serveur MCP et IA

| Menace                                           | Contrôle                                                                                                                                                                                                           | État                                                              | Preuve                   |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- | ------------------------ |
| Abus d'un tool (tool abuse)                      | Scopes minimaux par tool, limite de débit par credential (lecture 1, mutation 5), schémas stricts, aucun `podcastId` en entrée, audit de chaque mutation tentée.                                                   | **testé**                                                         | POC 9, ADR-0009          |
| Action publiante déclenchée par une IA           | Confirmation humaine à usage unique, expirante, liée à la demande et au contenu exacts ; si le contenu change après l'approbation, elle tombe.                                                                     | **testé**                                                         | POC 9                    |
| Injection de prompt via présentation ou document | Les garde-fous bornent les dégâts (scopes, podcast, confirmation, validation des sorties) sans empêcher l'injection elle-même. Une IA qui lit une page hostile peut être manipulée dans les limites de ses droits. | **résiduel** : non traité par construction                        | POC 9, limites           |
| Écrasement du travail humain par un agent        | Précondition d'empreinte (`expectedHash`) et de révision (`expectedRevision`) : conflit explicite plutôt qu'écrasement.                                                                                            | **testé**                                                         | POC 9                    |
| Coût IA incontrôlé                               | Quota de dépense par credential et par podcast, budget mensuel, coupe-circuit.                                                                                                                                     | **absent** (seule la limite de débit existe)                      | —                        |
| Sorties de modèle appliquées sans contrôle       | Validation par schéma avant toute écriture ; pas d'application directe d'un texte libre.                                                                                                                           | **testé** pour les tools existants ; à reproduire pour les futurs | POC 9                    |
| Fournisseurs IA (données envoyées)               | Liste des sous-traitants, minimisation de ce qui est envoyé, contrat. Décision du propriétaire.                                                                                                                    | **conçu**, décision ouverte                                       | `docs/open-questions.md` |

### 5.4 Média et enregistrement

| Menace                                                  | Contrôle                                                                                                                                                                                                                                                                                                                 | État                                                                                                                                                                                                                         | Preuve                                                                        |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Perte d'un enregistrement                               | Egress écrit sur disque persistant, envoyeur vérifié par SHA-256, superviseur, récupération des fichiers MP4 interrompus.                                                                                                                                                                                                | **testé** (crash d'Egress, stockage coupé, redémarrage du SFU, départ de participant)                                                                                                                                        | [ADR-0005](adr/ADR-0005-sorties-egress-locales-et-envoyeur-verifie.md), POC 3 |
| Altération d'un fichier après coup                      | Empreinte SHA-256 enregistrée à l'envoi, objets en écriture seule, journal des téléchargements. Pas de signature ni de stockage immuable.                                                                                                                                                                                | partiel : empreinte **testée**, immuabilité **conçue**                                                                                                                                                                       | POC 3                                                                         |
| **Traversée de chemin par l'identité d'un participant** | Le chemin de sortie d'Egress est construit avec l'identité du participant (`<salle>/<identité>-<type>-<piste>`). Une identité choisie par l'utilisateur contenant `../` pourrait écrire hors du dossier prévu. | Signed URL réutilisée ou divulguée                      | URLs de téléchargement courtes, liées à l'utilisateur et à un objet, audit des téléchargements.                                                                                                                                                                                                                          | **absent**                                                                                                                                                                                                                   | —                                                                             |
| Téléversement malveillant (assets, exports)             | Liste de types autorisés, taille maximale, analyse du contenu réel (pas l'extension), pas d'exécution, stockage hors de la racine web, nom de fichier généré par le serveur.                                                                                                                                             | **absent**                                                                                                                                                                                                                   | —                                                                             |
| Enregistrement sans consentement                        | Indication visible, consentement journalisé avant démarrage, commande `GRANT_CONSENT` dans la régie.                                                                                                                                                                                                                     | partiel : la commande et son contrôle sont **testés** ; l'interface et la politique légale sont **absentes**                                                                                                                 | [POC 6](pocs/poc-06-regie.md)                                                 |
| Salle LiveKit rejointe sans droit                       | Jeton de salle signé côté serveur avec droits minimaux (`canPublish` selon le rôle), expiration courte, un jeton par participant.                                                                                                                                                                                        | **absent** (le POC utilise la clé API directement)                                                                                                                                                                           | —                                                                             |
| Participant qui capture les pistes des autres           | Les invités n'ont pas le droit de s'abonner aux pistes de la régie au-delà de ce que le rôle exige ; les egress sont des participants cachés.                                                                                                                                                                            | partiel : participants egress cachés **constatés** ; droits d'abonnement **absents**                                                                                                                                         | POC 3                                                                         |

| Menace                               | Contrôle                                                                                                                                                                                                                      | État                                                                                          | Preuve                                  |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------- |
| Fuite de secret dans Git ou le front | Secrets générés localement dans `.local/` (ignoré par Git), jamais dans le dépôt ; scan des secrets en CI (gitleaks) ; gestionnaire de secrets en production ; rotation et révocation documentées.                            | partiel : génération locale **faite**, scan en CI **jamais exécuté**, gestionnaire **absent** | `AGENTS.md`, `.github/workflows/ci.yml` |

| Injection (SQL, commande)            | Requêtes paramétrées, aucune concaténation ; appels à ffmpeg et Docker avec tableau d'arguments (pas de shell) pour tout ce qui vient d'une entrée.                                                                           | partiel : appels à ffmpeg sans shell dans les POC ; pas de base de données encore             | POC 4, POC 3                            |

## 6. Risques résiduels prioritaires

Classés par gravité estimée × probabilité, à traiter avant toute exposition publique :

1. **Authentification : socle fait, pas fini** : pas de MFA, pas de récupération de mot de passe, limite de tentatives par e-mail (un attaquant peut verrouiller le compte d'une victime) ; scrypt non réglé sur le matériel de production.
2. **Le superviseur d'enregistrement du POC 3 n'est pas branché sur l'API** : il doit n'accepter que des identités UUID issues de l'API, et être promu en service.
3. **WebSocket collaboratif** : le jeton passe dans l'URL (journaux, proxys) ; pas de limite de taille de document ni de connexions par utilisateur.
4. **Journal d'audit du serveur MCP en mémoire** : à brancher sur la table d'audit de l'API.
5. **Injection de prompt par le contenu lu par un agent** : bornée, non éliminée ; à rappeler au propriétaire lors de l'ouverture de scopes d'écriture.
6. **Coût IA sans plafond** : aucun quota de dépense.
7. **CI jamais exécutée** : aucun des contrôles de chaîne logicielle (secrets, dépendances) n'a été vu fonctionner.
8. **Consentement et cadre légal de l'enregistrement** : décision du propriétaire, non prise.

## 7. Ce qui n'est pas couvert

- Aucun test d'intrusion n'a été fait, ni par un tiers ni de façon automatisée au-delà des 24 attaques du POC 8 et des cas de refus des tests MCP.
- La sécurité du transport (TLS, TURN, durcissement du SFU) n'est pas étudiée : tout tourne en local.
- Les menaces internes (opérateur malveillant, compromission du serveur) sont listées comme acteur mais pas traitées contrôle par contrôle.
- Le modèle de menaces sera à refaire quand l'API, l'authentification et le stockage réel existeront : plusieurs lignes ci-dessus passeront de « absent » à « à vérifier ».
